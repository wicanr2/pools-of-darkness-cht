# 018 片頭字幕的原版來源

2026-10-25。Issue：[#10](https://github.com/wicanr2/pools-of-darkness-cht/issues/10)。
來源與逐幀時序已確認，[字幕規格024](../spec/024-intro-subtitles.md)的八組台詞為CONFORMED。動畫HD仍為DRAFT。前置：[研究003](003-dosgolem-startup.md)、[004](004-output-paths.md)。

## 正常原版路徑

沿既有G2的常駐`ADLIB.COM`、程式路徑`C:\POD\SND.COM`及`CONTROL.EXE`鏈，不送跳過鍵。
原版唯讀掛載，只有獨立scratch與畫格輸出可寫。每2000萬指令擷取一次，至12億指令，共59組320×200色號及768-byte色盤。
原始輸入、seed設定檔與探針SHA-256、完整命令及收據雜湊見[018-intro-source.json](018-intro-source.json)。
工具沿`dosgolem-go-ebiten:1.24-r1`映像，探針版本以收據中的二進位SHA為準，不以目前分支HEAD代替建置版本。

EXEC紀錄證實`VACE.EXE`正常exit=0，之後`GAME.EXE`已啟動。原版程式與存檔未改。
本收據不把後續GAME的自然DEMO列為字幕證據，也不把指令數當成正式顯示時間或亂數對拍。

## 採樣結論

- 字幕區`[0,168,320,32]`的RGB去重得到15組，其中第2–9組是八組開場字幕。
  其他組是版權、空白、TITLE、製作群與GAME畫面，不混為片頭台詞。
- 八組字幕皆已逐組目視校讀，英文逐字稿與繁中草稿只留本機`workplace/probe/intro-source-v1/subtitle-draft.json`。
  專名沿正式詞表的「恐怖魔王」「王國」。初次粗採樣時尚未加入正式顯示表，後續接入見下節。
- 收據記錄每組首次與末次採樣指令數、配對色號與色盤SHA、字幕區RGB指紋及文字草稿SHA。
  這些範圍只說明採樣時可見，不是精確出現／清除時序；首次繪製、遮擋與語系切換仍未知。
- 已證實字幕在VACE畫面可見；字幕是否直接封在BMA畫格中仍沿研究004的強推論。
  沒有因此新增未經證實的檔案格式或修改原版動畫、判定與執行流程。

## 重生與下一個閘門

1. `bash tools/movie-source-receipt.sh <新名稱>`產生正常原版採樣，不覆寫舊收據。
2. 將已校讀草稿放進該本機收據目錄，再在`sosb-img:r1`內執行
   `python3 -I tools/movie_subtitle_inventory.py --capture <收據目錄> --proof docs/re/018-intro-source.json`。
   [盤點工具](../../tools/movie_subtitle_inventory.py)只輸出去重圖與來源證據，不修改遊戲或字型。
3. 先補首次繪製與清除的細格證據，再決定呈現層的辨識守衛與回退契約。
   達READY後才接入，另驗2／3倍、F8／F12、原版狀態與閃現0。

原始配對畫格與目視對照不加入Git。片尾`FINAL`及完整動畫HD尚未完成，正式台詞按既有private文字表政策保存。

## 細格時序與證據審查

以[時序探針](../../tools/movie_timing_probe.go)沿`session.Owner`的正式BootOriginal、Deliver、Advance介面冷啟動。
每回合96250步、時脈50%，與`pod-play`預設相同。不送鍵、不使用快照或座標注入。Frame只讀取畫格，回合結束時記錄視窗會呈現的最後畫格。
`bash tools/movie-timing-receipt.sh <新名稱>`在既有Docker映像建置並執行5100回合。
以`python3 -I tools/movie_timing_check.py --capture <收據目錄> --proof docs/re/018-intro-timing.json`在影像工具容器整理。
完整輸入、探針與原始收據SHA見[逐幀證據](018-intro-timing.json)。這些數字是本次固定條件的觀測，不作字幕計時器。

- 已證實：八組底部32列的色號圖樣在首次可見畫格即完整；觀測到的淡出只改色盤，沒有逐字或半句繪入。
  色號7為灰階前景，最高170；背景為黑，第四組用176，其餘用32。其他色盤槽會隨動畫改變，不能拿全色盤雜湊綁字幕。
- 已證實：第1、2、6組淡至全黑時，顯存仍暫留同一字幕圖樣。因此探針另保存色號及使用中色盤的轉換，不能只按RGB去重推定清除時點。
  全黑的圖樣沒有可見原字，不能當作原字閃現。
- 審查結論：規格024的八組色號SHA加使用中色盤守衛，已有最小充分來源證據，可以接入呈現層。
  灰階0–170間的淡出渲染是呈現契約；未逐值觀測的DAC亮度不稱原版精確時序。
- 八組繁中及英文正式台詞沿`text/host-text.<語系>.tsv`保存。字型已按正式表重建，2843字，兩種尺寸的SHA與原版相同，沒有缺字需要新增。

這份證據只涵蓋目前主機回合可見畫格，不代表每次顯存寫入皆已研究。原始圖與色號只留本機；正式台詞按既有private文字表政策保存。

## 正式呈現層與正常視窗驗收

`apps/pod/movie_subtitles.go`只讀最後呈現畫格，按八組SHA與使用中色盤辨識，再從目前語系的正式表取台詞。
不設計時器、不延續上一句，不要求HD主題存在。全句換行與字型檢查通過後才清除底部32列，失配或缺字則整句保留原版。
英文正式表保留完整原句，交既有函式按新字型重新換行，避免把舊換行帶入後超過四行。

`bash tools/movie-play-receipt.sh [subtitles|base] <新名稱>`產生兩條正常冷啟動視窗收據。
不送DOS鍵；字幕路徑在第一句操作F8、F2、F12，之後完整播放八句。每句首次可見畫格、末句淡出與清除均抓圖。
F10在回合推進前抓圖，因此檔名602對應已呈現的第601回合，其他組亦同。
在`sosb-img:r1`內用`python3 -I tools/movie_play_check.py --capture <收據根目錄> --source-proof docs/re/018-intro-timing.json --proof docs/re/018-intro-runtime.json`核對。

結果見[正式收據](018-intro-runtime.json)：

- dosgolem來源提交`e47af3e`，受測執行檔SHA為`f737659169253e5df20f32f07f4397681273bb68ca1df80dc65781cb330d5971`。
  已將同一受測檔設為本機預設，371檔HD主題不變。
- 兩條5100格路徑終點490875000步，CPU、記憶體、色號、色盤與127個DOS檔案一致，且與只讀來源探針一致。
  前端語言／字級等偏好獨立比較，不冒充DOS存檔。
- 18張配對截圖通過：八組首次可見台詞、雙語、2／3倍、F12原版，以及末句淡出與清除。
  差異只在原版字幕區；含海報的視窗中央與合成圖一致。八句繁中首次畫面已逐句目視，沒有裁切或缺字。
- 正常字幕路徑閃現0。實際來源畫格測試另覆蓋兩語言各兩倍率及各淡出狀態、來源／色盤失配、缺少語言與缺字回退。
  延後一格的正對照能被既有量尺偵測，沒有修改量尺來通過。
- `apps/pod`及`cmd/pod-play`測試通過；繁中16／24與英文16／24四組字型覆蓋均缺0字。

片尾`FINAL`與動畫HD保持未知或DRAFT，不由這組字幕收據外推完成。
