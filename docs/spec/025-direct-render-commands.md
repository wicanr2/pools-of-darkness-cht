正式範圍逐條達READY及CONFORMED；不以一個可行原型外推全部繪圖，不預告固定FPS倍數。

### 效果批次與效能勘誤（CONFORMED；先READY後實作）

第一輪完整正常DEMO的CPU／RAM及全部有序事件一致，但六支完整呼叫成本比原路徑差，不能啟用此版作加速完成。
原因是REP先擴成逐byte效果清單，再逐項驗證、提交與重建命令，丟失現行COPY／FILL的批次優勢。
修正為有序的緊湊HostTransfer，記錄目的、寬度、次數、方向、擁有的來源資料或填色值及原Step／CS:IP。
維持相同的逐byte相容寫入與VideoWrite，命令一次提交。複製來源與目的重疊或段內環繞時保留逐byte的順序計算。
每份計畫只含完整已驗區塊的前綴；後續區塊失配時截斷該區塊的全部效果，回到該區塊原入口，不丟棄已驗前綴再重做。
此為區塊原子性，前綴仍須完整驗證與原子提交；不得保留失配區塊的暫存器、旗標、時間或部分寫入。
除錯predicate、監看與事件仍禁止越過。緊湊表示須另以原版完整RAM、有序寫入、重疊讀回、資料壽命與成對成本驗證。

三支小型共享常式增加完整呼叫快速計畫，先達READY並已通過下列正式驗收。原始定位為1ED4:1A5C–1A7F、1A7F–1A93及1D1F:046E–0487，沿IDA同一份bytes。
Move指令數向前11、向後16；標準週期119／124加5N，DOSBox成本為指令數加N。Fill為7道、70+5N週期。
清零N偶數9道、74+5floor(N/2)；N=1時10道75週期；其餘奇數11道、78+5floor(N/2)。DOSBox另加實際byte／word迭代次數。
返回、段、暫存器、方向、算術旗標與參數清除從原指令推導，獨立原版oracle確認後才可列已證實。
目的與返回堆疊或程式重疊、段環繞、不安全拷貝方向或不足預算時回區塊／原版，不猜效果。非繪圖記憶體呼叫亦保留同樣完整副作用。
程式指紋只在同一份純計畫內快取，因計畫拒絕寫入所有已編譯程式區，迴圈重訪的bytes不會改變；不跨Advance快取資格。
