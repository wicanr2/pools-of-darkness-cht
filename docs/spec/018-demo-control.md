# 018 開場 demo 控制

狀態：CONFORMED，限本文件列出的 v1.10 與正常按鍵路徑。Issue：[#13](https://github.com/wicanr2/pools-of-darkness-cht/issues/13)。

## 行為

- PLAY／DEMO 選單等待玩家選擇，不自動開始 demo。
- 玩家明確選 D 才進入 demo。demo 中的一般遊戲按鍵改為中斷要求，該按鍵不送進遊戲。
- 經原版結束流程返回 PLAY／DEMO 選單；返回後可再次選 D，或選 P 正常遊玩。
- 控制只影響開場選單與正在中斷的 demo。正式遊戲不改停止旗標、雙方存活數或逾時值。
- 原版檔案不改，控制寫入只在記憶體中進行。語系、HD、F12 不改這項操作。

## 本作證據

輸入為安裝版 1.10。`GAME.EXE` 的 SHA-256 是
`35ad635e558852925b7028a921aacafc2df8e84be24a8a1136c6267471948d69`；
`GAME.OVR` 是 `885d6a07a3658f0688dc9d0630dfa984683a3d1d1e515a8e9909d29f62012485`。
EXEPACK 解壓後映像與載入位置沿 [研究 004](../re/004-output-paths.md)。

下列原始定位由 IDA Pro 9.4 的 16-bit 匯出確認。主程式使用 dosgolem 執行期 `16AF:IP`，
overlay 使用 `GAME.OVR` 檔案位移，兩者不混用。

| 原始定位 | 語意 | 等級 |
|---|---|---|
| `16AF:0141`、`029F` | 選單逾時 `DS:AAE8–AAEB` 分別設 3000、5000 | 已證實 |
| `16AF:016F`、`02CD` | 選單回傳索引存 `DS:7DDE` | 已證實 |
| `16AF:01B0`、`01B7` | 索引 1 時設 `DS:880E=1`，為 demo | 已證實 |
| `16AF:0276` | 遠呼叫 `16EF:0025`，進入原版主迴圈 | 已證實 |
| `16AF:027B` | 主迴圈返回，接原版清理呼叫 `1728:002A` | 已證實 |
| `GAME.OVR:0x2B64–0x2B9B` | `DS:7DE6` 在 ECL 進入／退出清零，迴圈檢查它及 `DS:8814` | 已證實 |
| `GAME.OVR:0x2ED9–0x2EF4` | 主迴圈依 `DS:8814` 等旗標決定退出，退出時清零 | 已證實 |
| `GAME.OVR:0x5217–0x522B` | 初次候選 `DS:7FF6／7FF7`，屬遭遇準備，不足以停止真正戰鬥 | 原始讀寫已證實；原候選語意已被正常戰鬥反證 |
| `GAME.OVR:0x368BB–0x36907` | `DS:A7CE／A7CF` 清零，再以角色 `+0x1EF` 當索引間接遞增；原 operand 為 `[di-5832h]` | IDA bytes 與間接資料流已證實 |

## 接入限制

正式程式已接入並啟用。可丟棄研究副本留在 `workplace/dosgolem/workplace/demo-control-research/`。
正常冷開機已確認一次按鍵可返回並接著進入建立隊伍；原始研究版返回太慢，
唯讀追蹤與同一戰鬥快照已補足下面的等待取消契約。證據足以實作，
60 TPS正常冷開機與模式補驗均已通過，固定收據見[驗收結果](#demo-conformed)。
失配時停用控制並回報原因，不沿用前作位址。

<a id="demo-initial"></a>

初始版本的前作簽章命中 0。冷開機後在 demo 中按 x，畫面仍繼續，
見 `workplace/probe/demo-control-v1/baseline/`。初次研究腳本沿舊收據送空白，
取消逾時後會停在選單，因此改用明確的 D；舊輸出保留為負對照。

2026-10-28 勘誤：`explicit-battle` 在第 5800 格仍是戰前對話，不能作戰鬥證據。
`combat-repeat` 的第 6900 格已在真正戰場，第 7100 格按 Esc 後，10300 格結束仍未返回。
此反證排除 `7FF6／7FF7` 作為實際戰鬥存活數；真正候選改追 `A7CE／A7CF` 的清零、間接寫入及退出消費端。
原失敗、圖片與 log 保留。當時規格未升 READY。
勘誤標記 `DEMO-RESOLVED-20261028`：舊候選已閉合，現況與不可變鍵見[正式驗收](#demo-conformed)，不得由本段重新開工。

第二版確認真正存活數會維持零，但仍在 CRT 計數等待。只按一次 Esc 的
`combat-trace` 最終返回一次，耗 99,740,710 步；前 40 筆唯讀樣本的停止旗標均為1、
存活數均為0，主要執行位置是線性 `0x1E1BF／0x1E1C2／0x1E1C4`。
這些位置對應 `1DF0:02BF` 的 CRT 迴圈，不重新研究 PIT 時序。

研究中的等待取消契約：只在 demo 已要求中斷後，確認完整 CRT 簽章唯一命中，
暫時把內圈第一個 byte 從 `26` 改為 `C3`，讓當下的 near call 返回。
原版外層的參數倒數、far return 與戰鬥清理照常執行。觀測到主迴圈返回後，
下一次 Advance 前恢復 `26`，再讓後續玩家輸入執行。正式遊戲與磁碟檔案不改。
位元組失配時不套補丁。測試需證明一鍵返回、補丁恢復、再次播放與正常進入遊戲。
這是中斷操作的預期等待差異，不稱為未中斷原版的逐步等價。

### 2026-10-28 等待取消的證據審查

CRT 取消後，正常路徑仍需45,402,291步。遊戲呼叫端主要等待
`int 66h / AX=0689h` 的音效狀態，見 `wait-1d700-ida.json`。
只定位呼叫端、參數與返回，不研究 driver／ISR／DAC／PIT 時序。

中斷期間的記憶體補丁白名單如下。來源由完整簽章及 epilogue 驗證，必須唯一；
這些是 dosgolem 線性位址，沒有與 IDA 檔案位移混用。

| 線性位址 | 原始 bytes | 中斷期間 | 用途 |
|---|---|---|---|
| `0x1E1BF` | `26` | `C3` | CRT 內圈返回 |
| `0x1D7A9` | `74` | `EB` | 音效狀態查詢後結束等待 |
| `0x1D7AD` | `BF 6A FB` | `E9 96 00` | 跳到原版 `0x1D846` 的 `mov sp,bp / pop bp / retf 2`，略過後續 cue 的緩衝清除、複製與播放 |

保留當時已在播放的音效及緩衝，由原版驅動完成，不送未知停止命令。
補丁在主迴圈返回後、下一次 Advance 前恢復原始 bytes。一般遊戲不套補丁。
已經中斷時重複按鍵只吞掉按鍵，不重新累計中斷要求。

同一份正常第7100格中斷前的完整機器／DOS快照，在獨立可寫存檔副本重播，
返回降至5,794,716步，回傳一次、補丁恢復為26、控制錯誤為空。
此項是診斷收據 `diagnostic-cue-v1/run.log`，不取代正常GUI驗收。
介面範圍、原始定位、輸入雜湊與失配行為已足以進入正式實作。

## 正式驗收

不可變鍵：`DOS/GAME.EXE/35ad635e558852925b7028a921aacafc2df8e84be24a8a1136c6267471948d69:runtime16AF:0276`。

正式來源 `a83043c02b28b7dc07db41a62a81300c0f0351f3`；Go 1.24.13 的乾淨建置，
執行檔 SHA-256 `b48485151486b0f2513820bbd85e49332aff2100511dbd45156729b6f1cf159b`。
[固定收據](../re/020-demo-control-runtime.json)保存來源、輸入、畫面與每條路徑的 CPU／RAM 摘要。

| 正常路徑 | 結果 |
|---|---|
| 空存檔冷開機，選單等待6500格 | 不自動播放，兩張選單逐像素一致 |
| 明確選D，對話按x，再選P | 中止／返回各一次，1510步返回，正常進建立隊伍 |
| 戰鬥按Esc，再選D重播，對話按Enter，再選P | 中止／返回各兩次，最後正常進建立隊伍 |
| 相同流程中切F12、2倍，再回繁中HD | CPU、完整RAM、原版色號與色盤終點同未切換流程 |
| 閃現量尺 | 非預期0；主動2倍切回HD的998格另列 |
| 記憶體與檔案 | 五個程式byte只在中斷期間改動，返回後還原；原始資料與壓縮檔SHA不變 |

重播入口為 `bash tools/demo-control-receipt.sh <新收據名稱> [binary名稱]`。
原始輸出在 `workplace/probe/demo-control-formal-v1/`，模式補驗在
`workplace/probe/demo-control-v1/formal-modes/`。前端F2／F12等快捷鍵保留呈現操作；
一般遊戲鍵中止demo，已驗x、Esc及Enter，空白走相同BIOS輸入路由。

| 不可變鍵 | 已閉合語意 | 證據位置 | 較早位置 | 必要勘誤 |
|---|---|---|---|---|
| `DOS/GAME.EXE/35ad635e558852925b7028a921aacafc2df8e84be24a8a1136c6267471948d69:runtime16AF:0276` | demo主迴圈、A7CE／A7CF存活數與可還原的等待取消 | 本節與固定收據 | 本文件 `demo-initial` | `DEMO-RESOLVED-20261028`，回鏈 `demo-conformed` |

`tools/demo_control_check.py --spec`會檢查這些入口與勘誤，缺項即失敗。

## 驗收

| 項目 | 必要結果 |
|---|---|
| 長時間停留選單 | 不自動進 demo |
| 對話中按一般字元 | 一次中斷要求，經原版流程回選單 |
| 戰鬥中按空白／Esc | 經戰鬥正常清理回選單，不停在空戰場 |
| 返回後按 P | 進入建立隊伍主選單，正式遊戲停止旗標不被控制 |
| 再次選 D | 可重新播放及再次中斷 |
| 寫入白名單 | 只寫本規格列出的停止、存活數、選單逾時與 BIOS 佇列尾位址 |
| 來源失配 | 控制停用且有明確紀錄 |
| 儲存與資料 | 原始資料 SHA 不變，測試產物只在獨立存檔目錄 |
